VibeSmith

在 AI 编码仓库漂移扩散之前完成审计。

VibeSmith 为多存储库团队提供了一个地方来审查 Cursor 和 Claude Code 工作流程中的活动组件、依赖性风险和上下文重用。它在 GitHub 上开源，现已提供预发行安装。

如果在回购三之后启动质量下降，请从这里开始。

VibeSmith 如何减少漂移

查找活动基线

统一清单+搜索显示哪些技能、代理、命令、挂钩和规则在项目中仍然处于活动状态。

重复使用而不丢失链接的片段

使用依赖项感知流程复制组件，使引导程序保持一致，而不是部分破坏。

在编写更改之前检查部署影响

预览并应用冲突策略，以便团队可以在更新共享设置之前判断爆炸半径。

在发布周前查看风险

依赖关系图、冲突审查和项目范围视图使隐藏的耦合更容易更早地被发现。

为什么这很重要

AI 编码 工具在解释许多内容之前先加速一个存储库

Cursor、Claude Code 和 MCP 是强大的本地工具。当团队需要跨多个存储库具有相同的操作清晰度时，系统差距就会出现。

Cursor 的会话范围上下文促使团队将可重用标准具体化，而不是依赖聊天内存。

Claude Code 中的多范围内存/设置会增加一致性开销，而无需共享操作层。

MCP 扩展了功能，但服务器范围和权限边界需要明确的审查规则。

第一周指标

第一周要测量什么

您可以从一个回购来判断早期价值。问题在于基线是否变得更加清晰，而不是大规模的推出是否已经发生。

结果01

更快的首次稳定设置

从安装到您的团队实际保留的基线的时间。

结果02

减少回购之间的意外

复制的规则、命令和组件在第一次重用后是否保持一致。

结果03

清理目标更明确

您可以在上下文质量下降之前删除哪些陈旧、冲突或过度增长的资产。

收养途径

首先通过一个存储库进行证明

您不需要组织范围内的迁移。从小处开始，测量漂移，然后只有在基线改善时才进行扩展。

步骤1

连接一个实时存储库

安装开源版本并扫描不断重新打开相同设置问题的存储库。

  • 输出：有源成分和漂移点的第一基线
  • 输出：安装摩擦音符

步骤2

审查重用和依赖风险

使用清单、详细信息和依赖关系视图来查看通过内存复制安装程序时出现的问题。

  • 输出：清理候选者
  • 输出：相关依赖风险

步骤3

仅在一个工作流程感觉更清晰后才进行扩展

在一个团队可以清楚地解释设置后，决定另一个存储库是否应该采用相同的基线。

  • 输出：保留/修复/扩展决策
  • 输出：更深层次合作的候选名单或 Pro

收养边界

当偏差已经损害交付速度时采用。

清晰的边界有助于多存储库团队快速做出决定，而不会过度投入。

牢固贴合

  • 三个或更多活跃仓库共享一个交付计划。
  • 由于规则是手动传递的，开球质量下降。
  • 发布审查反复发现较晚的依赖性问题。

还不理想

  • 具有稳定标准和低更改频率的单一存储库设置。
  • 工作流程尚未准备好为组件审核决策定义明确的标准。
  • 工作流程期望一键式自动化，无需部署规则。

当前范围（有意）

目前的范围有意保持狭窄。这一目标是更广泛的自动化承诺之前的明显证据。

  • 没有强制存储库重写。首先映射现有结构。
  • 云范围内的策略自动化是后期阶段，而不是第一阶段。
  • 仅在来自真实回购审计的重复证据后，共享推出层才会扩展。
