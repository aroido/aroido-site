Small teams often postpone writing because conversation feels faster. That works for a while, but only while the work still lives in one person's head.

We write earlier for a different reason. Writing forces the shape of the decision to become visible before the scope grows.

In practice, that means:

- A spec exists before implementation spreads.
- A product page exists before the message is widened.
- Release notes exist before a change becomes old context.

The point is not documentation volume. The point is decision clarity.

If we scale before the decision is legible, we usually end up scaling confusion instead of the product.
