VibeSmith

AI Agent Components Manager for Cursor and Claude Code.

VibeSmith unifies Skills, Agents, Commands, Hooks, and Rules in one local-first workspace so power users can scale without configuration chaos.

Build Status: Active Focus: Multi-repo AI coding ops

POSITIONING

Who It Fits

Best fit

Teams operating 3+ active repositories

Configuration drift grows rapidly when each repository keeps its own evolving AI coding setup.

Best fit

Leads needing predictable delivery quality

A component map and dependency visibility help teams catch risky coupling before release windows.

Best fit

Teams onboarding contributors frequently

Instead of oral handoff, newcomers can start from a structured inventory and operating policy.

Problem

Teams running AI coding workflows across multiple repositories lose reliability when rules, hooks, and command assets are scattered.

Approach

VibeSmith creates one operating layer for Skills, Agents, Commands, Hooks, and Rules with searchable structure and dependency visibility.

Experience

Instead of manually checking folders, teams review active components, coupling, and impact in one dashboard flow.

Outcome

Faster onboarding, lower configuration drift, and more predictable release cycles for AI-assisted development.

SIGNALS

Why Now

  • Cursor docs state that LLMs do not retain memory between completions, so reusable rules and context layers become essential.
  • Claude Code supports memory and settings at multiple scopes, which is powerful but harder to keep consistent across many repos.
  • MCP enables external tools, but server setup and approval boundaries add operational load for each project.

Evidence sources

  • Cursor Rules for AI
  • Claude Code Memory docs
  • Claude Code Settings docs
  • MCP Authorization specification

ROLL-OUT

30-Day Rollout Blueprint

The rollout is staged to prove measurable wins before broader expansion.

Week 1

Baseline and repository mapping

Capture current setup cost and map component assets across active repositories.

  • Deliverable: repo/component inventory snapshot
  • Deliverable: risk map of critical coupling paths

Week 2-3

Team workflow adaptation

Standardize operating routines for review, search, and change-risk checks.

  • Deliverable: shared review checklist and owner model
  • Deliverable: onboarding runbook for new contributors

Week 4

Outcome review and scale decision

Compare baseline versus pilot metrics and decide whether to expand scope.

  • Deliverable: before/after metric report
  • Deliverable: expansion plan with risk controls

DECISION GATES

When expansion is justified

Keep pilot scope if

  • Setup time has not improved enough to clear onboarding pain.
  • Context mismatches still appear in core delivery paths.
  • Review owners and policies are not yet stable.

Expand rollout if

  • Setup time reduction is sustained across new repositories.
  • Risky coupling is surfaced earlier than current release checkpoints.
  • Team members follow one shared operating flow with low exception rate.

FAQ

Adoption FAQ

Do we need to change our current repository structure?

No full rewrite is required. Pilot rollout maps existing assets first and standardizes gradually.

Can we use this with both Cursor and Claude Code at once?

Yes. The goal is to keep component operations consistent across both toolchains.

What does success look like in the first month?

Faster setup, fewer context mismatches, and earlier detection of risky dependencies.

How do we start without overcommitting?

Run a scoped 2-4 week pilot on one active project, then expand only with measured gains.
