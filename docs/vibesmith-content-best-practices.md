# VibeSmith Project Page Content Best Practices (2026)

## Goal
- Reduce repetition and long-form copy.
- Make value, fit, and adoption path scannable in under 30 seconds.
- Keep SEO quality while improving conversion intent.

## Research Signals
- Nielsen Norman Group: concise/scannable/objective writing improves usability and task completion.
  - https://www.nngroup.com/articles/concise-scannable-and-objective-how-to-write-for-the-web/
- Nielsen Norman Group: users scan heading layers first (layer-cake pattern), so heading hierarchy must carry meaning.
  - https://www.nngroup.com/articles/layer-cake-pattern-scanning/
- Nielsen Norman Group: progressive disclosure reduces overload by showing advanced detail later.
  - https://www.nngroup.com/articles/progressive-disclosure/
- Nielsen Norman Group: users do scroll, but top-of-page hierarchy still determines attention.
  - https://www.nngroup.com/articles/scrolling-and-attention/
- Google Search Central: people-first, helpful, original content is preferred over SEO-first filler.
  - https://developers.google.com/search/docs/fundamentals/creating-helpful-content
- GOV.UK Content Design: answer user needs directly and avoid FAQ-style duplication when core flow can carry answers.
  - https://www.gov.uk/guidance/content-design/writing-for-gov-uk
- W3C WCAG 2.2: headings and labels must describe purpose clearly for scan/accessibility quality.
  - https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels

## Applied Rules
- One section = one question.
- Keep heading language outcome-focused, not internal jargon.
- Remove repeated sections that restate the same pain/solution pair.
- Keep proof concrete: product visuals + measurable pilot metrics.
- Keep adoption boundaries explicit (strong fit / not ideal yet / out of scope).
- Place install/download and pilot CTA after proof and fit checks.
